Let's get you started.

Pick what you want to do. You don't need the protected build just to play.

Use the regular client.

Look in Downloads for Maro-Updated.jar. This version has no Maro sign-in or activation key.

  1. Use a Minecraft Java 1.21.11 profile with Fabric Loader and Fabric API.
  2. Close Minecraft. Put Maro-Updated.jar in that profile's mods folder.
  3. Keep only one Maro JAR in the profile, then start Minecraft.
  4. Choose Singleplayer for your worlds or Multiplayer for servers.
You still use your normal Minecraft account. The owner-only licensing service is separate.

Use the tester bundle.

The file in Downloads starts with Maro-Obfuscation-Tester-. It contains the obfuscated JAR, a signature, and public verification material.

  1. Use a separate Minecraft profile. Both editions use the same mod ID, so they cannot be installed together.
  2. Use the signed Maro-Protected-Test.jar for your authorized inspection.
  3. Keep the owner kit and private mapping separate from the tester exercise.
The included preview uses disposable test configuration. Its test service is stopped after validation, so it cannot unlock real owner access. navo is a username, not a password. A live sign-in test needs an owner-provisioned service and a matching rebuilt client.

Obfuscation raises inspection effort. Shipped client code can still be inspected and changed.

Set up your private owner account.

There is no public registration. Do these steps on a host you control, with the owner setup kit.

  1. Prepare the service. You need an HTTPS domain, a private server, Python 3.11 or later, and protected persistent storage.
  2. Create navo privately. The provisioning tool asks for a new password and verifies your authenticator app. It binds the account's permanent ID on the server.
  3. Save the important pieces. Store the activation key and recovery codes when they are shown once. Keep signing keys private.
  4. Build the matching protected client. Export the server's public configuration, build the separate protected edition, and sign it with production release keys.
  5. Sign in. Enter your password and a fresh app code. Paste the activation key when asked. Later sign-ins normally use your saved device credential.
Show the provisioning command

From the project root, after installing the kit's Python dependencies. Replace the example host with yours. Use a private terminal; do not put passwords or keys in command arguments.

protection/.venv/Scripts/python.exe protection/server/admin.py provision --state C:/MaroPrivate/license --origin https://YOUR-LICENSE-HOST --output C:/MaroPublic/client-public.json

The complete deployment and signing commands are in protection/README.md.

Something went wrong?

Wrong code: wait for a new six-digit code in your authenticator. Each code can be used once.

Can't connect: check your internet connection and the owner's HTTPS service. Protected features stay paused until verification succeeds.

Lost authenticator: use your password and one unused recovery code with the owner recovery tool. It enrolls a new authenticator and signs out old devices.

Too many devices: on a signed-in device, open Manage devices and sign out the other devices. If no device is available, use the owner recovery tools.
